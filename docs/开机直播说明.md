# 开机直播 · 0.2.9

## 先在电脑验证，再在电视复测

入口：**右上角设置 → 开机与桌面**。

| 入口 | 功能 |
| --- | --- |
| 默认桌面 | 显示系统是否将栖屏确认为默认 HOME |
| 开机自动打开直播 | 默认关闭；开启后下一次系统重启生效 |
| 直播应用 | 选择已安装应用，与首页“直播”共用绑定 |
| 立即试播 | 立即打开所选应用，用于核对绑定和系统启动能力 |
| 启动状态 | 查看最近一次处理原因、运行时长、启动标识及默认桌面状态 |

历史反馈记录了默认桌面与轻量模式已生效；个人设备照片参数已移除。本轮没有直接连接目标电视，不能仅凭历史反馈断定未自动打开的具体触发顺序。

本版修正代码中已确认的问题：此前 onPause、焦点丢失和重复 HOME 请求都会调用取消，并把本轮标记为已处理。现在这些系统事件仅暂停倒计时，恢复后重新显示完整 3 秒。是否解决这台电视的实际问题，需要下面的重启步骤确认。

### 电视测试步骤

1. 用 Android Studio 打开完整源码工程，先在模拟器检查页面。向电视覆盖安装时，用安装旧版时的同一份 `qiping.jks` 和别名签名；包名不变、versionCode 升为 11。不需要先卸载，原有应用绑定和偏好继续沿用。
2. 进入开机设置，核对默认桌面、已开启的开关和直播应用，按 **立即试播**。若手动也打不开，应先检查绑定应用是否可用。
3. 在电视系统菜单执行真正的 **重启**。重启后先不按遥控键，观察桌面上的倒计时和直播应用是否打开；启动条件准备较慢时最多等待约一分钟。
4. 按 HOME 返回桌面，等待至少 5 秒，应该保持桌面；从直播退出也不应再次自动打开。
5. 再重启一次，在倒计时按返回，确认取消本次；开关仍保持开启，下次重启可以继续尝试。
6. 若仍停留桌面，拍下 **设置 → 开机与桌面 → 启动状态** 的“最近记录”。长内容可以上下滚动，右键到关闭按钮，返回关闭并恢复原焦点。

**遥控器关屏再亮屏可能只是待机唤醒。** 本版只在系统重启后自动打开，不新增每次唤醒都打开的行为。对比启动状态中的“当前启动标识”和“距系统启动”：若标识没变、时间继续累加，就没有检测到新的系统启动。厂商计数异常也可能影响判断，需要结合记录核对，不能直接认定是权限问题。

## 启动行为

- 默认 HOME Activity 进入开机窗口后，等待成为默认桌面、回到前台、获得窗口焦点、应用列表准备好、所选应用可用。
- 条件齐备后在主页直播场景显示 3 秒倒计时。重复 HOME 请求、临时 onPause 或焦点丢失不消耗本轮机会；恢复后重新开始完整倒计时。
- 返回、方向键、确定等按键或触摸会明确取消本轮。方向键或触摸同时正常导航；倒计时期间返回键只取消。
- 用户已经操作过桌面时不再自动打开，包括开机广播稍晚才到达的情况。
- 真正调用 startActivity 前同步记录本轮已处理。失败、直播崩溃、退出、返回 HOME 和栖屏进程重建都不会再次请求打开同一轮。
- 等待起点持久化：首次有效检查后最多等 60 秒，不因重复 HOME 或进程重建无限延长；离开前台时停止轮询。
- 开机已超过 10 分钟才进入桌面，或倒计时跨过这个窗口时，本次不自动打开。
- 应用扫描初次失败或目标暂未出现时，最多补充扫描 3 次；这是重读应用列表，不是反复启动应用。
- 系统启动请求失败后留在桌面。状态“已向系统发送打开请求”只表示 startActivity 返回时没有抛出异常，不证明应用成功显示或已开始播放。
- 自动播放哪个频道、是否需要登录或关闭应用自己的提示，由直播应用负责。

## 启动状态如何理解

| 显示 | 含义 / 下一步 |
| --- | --- |
| 已开启，等待下一次系统重启 | 开关开启时不会立刻跳走；先做真正重启 |
| 通过应用入口打开 | Android Studio Run 或普通应用入口，本轮没有当作开机 HOME |
| 检测到遥控器或触摸操作 | 用户操作取消了本轮，不会关闭下次重启的功能 |
| 等待默认桌面 / 前台焦点 / 应用列表 | 启动条件尚未齐备，仍在有限等待期内 |
| 等待启动条件超过 60 秒 | 本轮已停止，下面保留当时缺少的条件 |
| 已超过开机后 10 分钟 | 当前进入桌面的时机不在开机窗口；需确认是否只是待机唤醒 |
| 所选直播应用暂不可用 / 读取失败 | 先检查“立即试播”和绑定，必要时重新选择 |
| 已向系统发送打开请求 | 已发出一次请求；若仍未显示应用，请保留此记录继续排查系统或应用行为 |
| 启动标识来源发生变化 | 系统计数可用性发生变化，本轮保守跳过；下次重启再测 |

查看状态时不会重新尝试打开，不会抹去已经记录的成功请求、失败或取消原因。没有用户操作且没有执行过请求的倒计时可以在 Activity 重建后重启；已经取消或执行过的轮次不能重放。

## Android Studio 仿真

1. 运行到 TV 模拟器，安装用于试播的应用，验证选择、立即试播、返回焦点以及启动状态弹窗。
2. 设栖屏为模拟器默认桌面，开启开机自动打开，然后真正重启模拟器。可在终端执行 `adb -s <模拟器序列号> reboot`，请使用测试模拟器的序列号。
3. 不按键观察倒计时；打开后按 HOME 验证不重复；再重启后按返回验证取消；关闭开关后再重启验证保持桌面。
4. Android Studio Run 是普通应用入口，会跳过本轮自动打开。Quick Boot 恢复快照可能沿用旧启动标识，不能替代系统重启。

`LauncherSmoke` 是可选、会修改测试偏好的模拟器交互脚本，本轮仅编译，未执行。主机上的 `StartupStateTest` 和 `StartupFlowTest` 已运行，用于验证启动状态与生命周期事件序列，不代替电视实测。

## 实现与限制

`StartupState` 保存开关、已处理标识、等待起点和最近结果。`StartupFlow` 处理等待、连续倒计时、用户取消和限时终止。`MainActivity` 提供实际前台条件，并且只有在默认桌面拥有焦点时请求打开应用。

API 24+ 优先读取公开的 `Settings.Global.BOOT_COUNT`，旧系统或计数不可用时用 `BOOT_COMPLETED` 写入的轮次。`BootReceiver` 只记录广播，不从后台启动界面；没有新增常驻服务、无障碍或悬浮窗。计数来源变化保守跳过一次，避免将来源变化误判成重启。

开机窗口和等待均使用 `SystemClock.elapsedRealtime()`，包括系统深睡眠时间，不受校时与时区调整影响。Android 允许 onPause / onResume 在新 Intent、睡眠等过程中往返，因此不能把单次 onPause 等同于用户取消。
