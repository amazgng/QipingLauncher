# 待机唤醒实现说明

WakeMonitor 使用 Application 上下文动态监听 SCREEN_OFF / SCREEN_ON，在 onResume / onPause 复核 PowerManager.isInteractive()；始终根据当前电源状态确认变化，忽略重复和过期方向。普通 Activity 返回不产生电源状态转换。

MainActivity 报告当前首页以及发起外部 Activity 的行为。从首页待机才准备唤醒启动；从桌面进入直播或系统页面后待机，保持原应用。监听只保存有界状态，不启动 Activity、不常驻服务、不持有唤醒锁。Activity 监听以弱引用关联。

WakeState 独立保存 wake_live_enabled、关屏标识、唤醒时刻、轮次及处理状态，默认关闭，不改变原 live_enabled。唤醒记录以同一系统启动的单调时间校验，最多等待 60 秒，提交已处理记录成功后才能发起启动。进程重建时若只有旧关屏证据、没有可确认的唤醒时刻，不猜测补启动。

WakeFlow 仅由前台桌面轮询。屏幕可交互、默认 HOME 确认、首页有焦点、无弹窗、目标应用就绪后，连续显示 3 秒倒计时。暂停或失去焦点重置可见倒计时；返回、方向键、确认、触摸取消本轮。电源 / 电视电源 / 休眠 / 唤醒键不误取消。系统重启流程和唤醒流程互斥处理一次打开请求。

Android 官方接口依据：
- [Intent：SCREEN_OFF / SCREEN_ON](https://developer.android.com/reference/android/content/Intent#ACTION_SCREEN_ON)：表示系统交互状态变化，需动态注册接收。
- [PowerManager.isInteractive](https://developer.android.com/reference/android/os/PowerManager#isInteractive())：用于读取当前交互状态。
- [Activity security](https://developer.android.com/guide/components/activities/secure-bal)：前台可见性与后台启动限制。本实现只由已显示的桌面发起应用打开。

这些接口不能保证所有海信固件、CEC 或进程清理方式均相同。实际电源监听及唤醒决定显示在启动状态中，供真机排查。
