# 设备信息与性能适配 · 0.2.14

## 入口

右上角设置 → 设备与性能。六张玻璃卡片可用触摸或方向键选择，确定查看完整详情。右上角刷新读数；右下角打开使用说明；返回键回到设置并选中原卡片。

## 读数说明

| 项目 | 含义 |
| --- | --- |
| 型号、制造商、品牌 | 当前安装设备的系统报告值，可能是厂商内部型号 |
| 安卓版本 / API / 系统构建 | 读取 Build.VERSION 与 Build.DISPLAY，不从 JUUI 版本推测 |
| 显示区域 | 系统分配给桌面的像素与密度；不等同于面板物理分辨率 |
| 系统总内存 | 内核可访问的总 RAM，可能小于标称 1GB |
| 当前可用内存 | 打开页面/刷新时的快照，会受其他应用影响 |
| 应用堆上限 | 单个应用可用的 Java 堆上限；不是整台电视的 RAM |
| 存储空间 | 应用所在数据分区的容量与可用空间；不包含系统分区和外接 U 盘 |

手机显示手机的信息，装到电视后才显示电视的信息。读取失败的字段显示“未能读取”；不会用零、目标机型或推测的安卓版本代替。无需额外权限，不读取序列号、账号、MAC 或 Device ID，不上传设备信息。

## 性能模式

- 默认“自动适配”：系统可见总 RAM ≤ 1.5 GiB、平台低内存标志、应用堆 ≤ 128 MiB，任一成立时选轻量档；无法读取总 RAM 时也保守使用轻量档。
- 手动“轻量模式”：在手机或高配置设备上也使用同样限制，用于检查画面和操作。选回自动后按当前设备重新判断。
- 个人设备快照已移除。实际程序始终读取当前设备，不将设备参数写死。
- 模式切换会重新加载当前背景，保持分类、应用绑定、开机直播设置和焦点。

| 限制 | 轻量 | 标准 |
| --- | --- | --- |
| 背景最大边 | 不超过显示区域，且 ≤ 960 px | 不超过显示区域，且 ≤ 1920 px |
| 模糊副本最大边 | 96 px | 128 px |
| 背景缓存 | 最多 2 张，并受 4 MiB 上限约束 | 最多 3 张，并受 20 MiB 上限约束 |
| 图标缓存 | 最多 16 张，每张 ≤ 96×96 | 最多 48 张，每张 ≤ 192×192 |
| 背景过渡 | 220 ms | 360 ms |

解码按 2 的幂采样；因此实际背景尺寸可能低于上表上限。维持 ARGB_8888 避免降低色深。上述字节预算只指背景缓存，不代表整个应用占用；切换期间的前后帧、解码中的图片、视图和图形系统还会使用内存。

## 生命周期

- 前台：仅按需解码。快速切换时取消待提交请求，后台队列最多保留一个等待任务；最终选择才会更新画面。
- 暂时失去前台：停止背景过渡、卡片焦点动画、时钟/网络定时刷新及新背景解码，只保留当前背景帧。
- 完全不可见：清空背景、玻璃着色器和应用图标引用。内存由系统回收，代码不调用 System.gc()、杀进程或清理其他应用。
- 返回：重新加载当前场景；应用列表恢复当前页。后台扫描完成时不重建隐藏界面。
- 内存压力：清理其他背景和图标缓存，保留当前场景或对应颜色背景。已经显示过的位图不会被强制 recycle，避免画布读取已回收图片。
- 解码内存不足：最多尝试一次更低分辨率；仍失败则保留分类渐变背景，不循环分配。

## 在手机上先检查

1. 使用 Android Studio 打开并运行 0.2.14 源码，保持与之前测试相同的签名，以保留已有绑定。
2. 设置 → 设备与性能，查看安卓版本、型号、内存；确认显示的是这台手机。
3. 点“性能适配”选择轻量模式，再返回首页快速切换五个分类，检查最终标题和背景相符。
4. 打开已绑定的应用，再返回栖屏，检查背景恢复、入口仍能打开。也可从全部应用第二页启动应用并返回，确认仍停留在原来的应用及所在屏。
5. 退出重进，检查轻量选择和应用绑定保留；再改回自动适配。
6. 设备页测试右上角刷新、每张卡片详情、返回、使用说明；大字和三档边距也可在手机检查。

## 电视上的后续检查

安装到目标电视后进入此页，核对安卓版本与内存读数。再检查遥控器移动、切换卡顿、从直播返回、默认桌面与真正重启后的开机直播。

手机或模拟器测试不等同于电视性能测试。本版最低 Android 9，使用 API 28 编译验证与 Android 9 模拟器检查；实际执行结果见根目录“验证记录.txt”。玻璃图标复用壁纸模糊缓存，不增加每帧图片解码；此处未声称电视帧率或实际进程内存下降幅度。
