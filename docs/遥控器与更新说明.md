# 遥控器导航与应用更新 · 0.2.14

本版保留原生 Java / Views 和既有遥控器导航规则，最低系统已提高为 Android 9（API 28），界面统一为随壁纸透色的玻璃图标。交付的是 Android Studio 源码工程，不包含预编译 APK。真实更新服务仍暂停接入。

## 全部页面的遥控器规则

| 场景 | 操作与结果 |
| --- | --- |
| 首页 | 左右选择五个分类，标题和背景跟随焦点；上键进入顶栏；下键打开全部应用。 |
| 首页最右侧 | 选中“全部应用”后再按右，直接进入全部应用；也可按确定。首页只有五个固定分类，没有虚构多页。 |
| 全部应用、更新列表、应用绑定页 | 上下左右选择真实存在的应用；每屏最多两行六列。 |
| 网格最右列 | 按右进入下一屏同一行的第一个应用；末屏没有这一行时落在末屏第一行。 |
| 网格最左列 | 按左进入上一屏同一行的最后一个应用。 |
| 整个列表末尾 | 继续按右保持当前选择，不跳到空位，也不循环回第一屏。 |
| 普通应用列表第一屏最左列 | 再按左返回首页；更新列表则返回进入它之前的页面。绑定选择页在边缘停留，避免误取消。 |
| 连续按住方向键 | 可连续移动焦点；跨屏后需松开再按，避免一次长按连跳多屏。 |
| 顶栏下键 | 回到本页刚才选中的内容；初次进入按空间位置选择。 |
| 确定 / Enter | 打开应用或执行当前操作；有真实更新提醒时显示“前往更新 / 打开现有版本”。 |
| 长按确定约 0.55 秒 / 菜单键 | 打开应用或首页入口管理；松开长按不会再次点击弹窗第一项。 |
| 设置、设备、开机页 | 用方向键在卡片间移动；确定进入或切换；返回恢复上一层焦点。 |
| 弹窗列表 | 上下选项；右键可进入底部按钮；底部左右选按钮、上键回到列表。 |
| 长篇说明 | 上下滚动正文；右键到按钮，按钮上键返回正文；返回关闭弹窗。 |
| 手机触摸 | 点击、长按仍可用；应用网格支持水平滑动翻屏。 |

界面没有页码、上一页或下一页按钮。列表两侧只在确有其他内容时显示淡色方向提示，它们不接受焦点，不需要点击。列表刷新按应用包名恢复焦点；应用消失时落到仍存在的相邻位置。设置、更新和管理弹窗返回时恢复对应入口。

上述规则覆盖栖屏自己绘制的所有页面。进入海信系统设置、第三方应用或应用商店后，由对应软件控制界面和遥控器响应，栖屏不能接管它们的内部焦点。

## 更新提醒当前能做什么

- 首页已绑定应用与全部应用卡片的左上角共用小型“更新”角标；右上角原有的绑定圆点保留。
- 首页“全部应用”入口在有可提醒更新时显示汇总角标。
- 按确定进入更新选择，遥控器可选“前往更新”“打开现有版本”或“稍后”。管理菜单也提供更新/应用商店入口。
- “全部应用”右上角和“桌面设置”右下角都可以进入应用更新列表。它使用相同玻璃卡片和边缘翻页规则。
- 接到真实版本清单后，按包名、已安装 versionCode、新版 versionCode、最低 API 以及清单有效期判断。使用 versionCode 比较，不按“1.9 / 1.10”等展示文字排序。
- 桌面前台收到系统安装/更新/卸载广播，以及从商店返回时，重新读取安装版本；只有已经安装到相应版本才清除提醒。点击“前往更新”或“稍后”不会提前清除。
- 更新动作打开配置的应用商店详情页，由商店处理下载、签名、兼容性、安装及用户确认。栖屏不自行下载或静默安装第三方 APK。

**当前工程没有预置真实更新数据源。** `app/src/main/assets/update-source.json` 保持空配置，因此首次运行的更新页会显示“尚未接入更新服务”，不会伪造角标，也不会把未检查的应用说成“全部最新”。没有接入的应用仍可以从管理菜单前往支持标准详情链接的应用商店；找不到商店时说明原因，并提供打开应用的选项。

要完成真实提醒的接入，还需要确认电视主要使用的应用商店，或提供具体应用的官方版本接口。不能把“已经安装/更新完成”的系统广播当作“有新版本可下载”，也没有读取所有通知来猜测更新。

## 开发者接入更新服务

本节用于 Android Studio 工程配置，电视使用界面不要求输入 URL 或 JSON。

1. 确认服务有权提供目标应用的真实版本、包名和最低系统要求；确认提供的是对应电视/发行渠道的版本。仅有商店名称，还需要可用的数据接口。
2. 将 `examples/update-source.example.json` 中字段替换为真实值，再写入 `app/src/main/assets/update-source.json`。
3. 服务返回 `examples/update-catalog.example.json` 所示结构。`schemaVersion` 为整数 1，`apps` 是数组。每项必须包含 `packageName`、整数 `versionCode`、整数 `minSdk`；`versionName` 可省略。
4. `storePackage` 必须是电视上实际商店的包名；`storeUriTemplate` 必须使用该商店支持的详情链接，并包含 `{package}`。固定商店包名可防止数据清单把用户导向任意处理程序。
5. 如果商店仅支持自有 URI scheme，替换模板即可；不要虚构海信或当贝的 scheme。实际商店是否能用遥控器完成更新，还需在对应设备上核对。

示例中的 `example.com`、`cn.example.*` 均为占位符，不是可用服务，也没有自动复制到应用配置中。

版本源只接受 HTTPS，沿用系统证书与域名验证；不忽略证书错误，不回退 HTTP。最多跟随两次重定向，响应上限 512 KiB / 5,000 个条目，连接与读取各有 5 秒超时，并有整体读取时限。旧安卓与具体服务器的 TLS/证书兼容性需要实测，连接失败会显示“暂时无法检查”。

默认在桌面前台首次进入时检查，此后成功结果 6 小时内复用；失败自动重试间隔至少 15 分钟，手动刷新可立即重试。同一时间最多一次请求。缓存的提醒最多保留 24 小时，时钟回拨使缓存失效。退出桌面不运行持续轮询服务。已发出的短请求可完成，Activity 销毁时取消。

清单下载不上传已安装应用列表：下载同一份服务目录后在本机匹配。配置变化时旧源缓存不复用；重复包名、非法版本、缺少必填字段或错误结构会使这次清单失败，不覆盖之前有效的结果。

APK 的安装渠道、签名、ABI 与电视兼容性最终由商店/安装器验证；版本源应准确列出适用于该渠道的版本。未配置服务、服务失败、源未覆盖某应用和“没有新版”是不同状态。

## Android Studio 核对顺序

1. 运行 `app`，使用方向键、Enter、Back。首页从影视向右走到全部应用，再按右应进入应用网格；返回应回到原入口。
2. 在测试模拟器安装足够多的可启动应用，检查首屏、末屏、末屏只有一个应用、两行之间移动和左右跨屏。手机测试时改用水平滑动。
3. 打开设置、边距选项、开机应用选择、设备详情、性能选择、使用说明和应用管理。全程只用方向、确定、返回；检查焦点清晰、长说明能滚动、关闭后焦点恢复。
4. 长按确定出现菜单后松手，菜单不应自动执行第一项；绑定页首屏按左不应取消绑定。
5. 更新源未配置时，应显示未接入，不出现虚假更新角标。设置真实服务后检查断网、空目录、错误响应、最低 API 不兼容和商店缺失。
6. 对一个已知有新版的测试应用，用遥控器进入商店并更新；返回栖屏，确认真实安装版本提高后角标消失。不要只以商店页面被打开作为更新完成证据。

`app/src/androidTest` 额外提供测试专用的 25 个内存条目和本地版本清单，用于测试翻页、角标、版本过滤、长按松手及进入商店的流程。这些数据只存在于测试源码，不写入生产 assets。测试商店是 ProbeActivity，不下载或安装任何东西；真实更新仍需第 6 步。

可先用 Android Studio/Gradle 构建 app 与 androidTest：

```sh
./gradlew :app:assembleDebug :app:assembleDebugAndroidTest
```

在测试模拟器安装这两个测试构建后运行：

```sh
adb shell am instrument -w cn.wengmang.qiping.tests/cn.wengmang.qiping.tests.LauncherSmoke
```

测试会调整桌面偏好及绑定，沿用既有测试套件的重置行为，只用于测试模拟器。此版本在交付环境中已编译测试源码，尚未执行模拟器或海信实机交互。

实现参考：[Android 电视导航](https://developer.android.com/training/tv/get-started/navigation)、[Android 应用商店详情链接](https://developer.android.google.cn/distribute/marketing-tools/linking-to-google-play)、[Google Play 应用内更新适用范围](https://developer.android.com/guide/playcore/in-app-updates)。本工程不依赖 Google Play Core；Google Play 的应用内更新不是本项目通用电视/第三方应用更新来源。
