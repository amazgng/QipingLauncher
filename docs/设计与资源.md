# 0.2.18 待机唤醒补充

开机与桌面页在原四张卡片下增加同风格玻璃开关条“待机唤醒也打开直播”，默认关闭。方向键从第二排卡片向下到新开关，再向下到启动状态。大号、特大字号和较大边距已纳入专项检查。壁纸、图标、玻璃绘制和其他页面布局保持 0.2.17。

# 0.2.17 增量设计说明

手机网页保持石墨玻璃风格，裁剪框为 16:9，滑块、复位与上传按钮适合窄屏触摸。裁剪不叠入桌面 UI，输出仅为图片。

原生图标形状、布局与六张内置壁纸沿用；亮度统计在后台读取 16×9 小样本，缓存为单个浮点值。深色透明度沿用，浅色背景加强石墨底色和银白描边的分离。切换时插值该亮度值，没有每帧解码、截屏或重新模糊。

运行诊断入口沿用设备页面底部操作区和启动状态弹窗；信息详情及日志由现有玻璃弹窗承载，遥控器上下滚动、右键进入按钮、返回回到上级。

# 0.2.16 手机传壁纸设计

延用 0.2.15 的六套风景、石墨银白玻璃和遥控器交互。既有个性化设计与资源说明见 history/0.2.15_设计与资源.md。

## 电视与手机交互

电视接收窗口使用现有 GlassPanel / GlassButton 和 SceneView 取色；二维码保持白底黑码及完整静区。三个操作为结束传输、放弃图片、应用壁纸，方向键可达；没有图片时跳过不可用按钮。上传后加载小尺寸预览，焦点转到应用按钮，确认前保留原壁纸。

手机页是随应用打包的 HTML/CSS/JavaScript，使用系统字体，无外部资源或云端上传。包含二维码直接连接、手动配对、六个目标分类、选图预览、20 MB 客户端校验、上传进度和状态轮询。图片名称只用 textContent 显示。

## 接收与文件生命周期

PhoneWallpaperServer 为限时 TCP/HTTP 会话，不注册 Android Service。只绑定所选 Wi-Fi / 有线私有 IPv4 地址，另绑定同端口本机回环地址用于 ADB 转发。没有局域网地址时提示检查网络。没有新增 Manifest 权限。

二维码在本机生成，包含 128-bit 随机会话凭据，放在 URL fragment；网页读取后从地址栏移除。手动配对使用 6 位码，单次会话最多允许 5 次错误尝试。每次开启都换凭据，最长 10 分钟。

服务检查 Host、Origin 和 Sec-Fetch-Site；上传和状态读取需要会话凭据。不提供目录或文件下载接口，不返回跨域许可。页面禁止缓存、嵌入框架和外部脚本，关闭 referrer。局域网 HTTP 不提供传输加密，请在可信家庭网络使用。

最多 3 个工作线程与 3 个排队连接；请求头上限 8 KiB，不接受重复头或 chunked/Expect 帧格式；请求和图片读取有超时，上传最多 20 MB，一次只处理一张。上传图片由已有 WallpaperStore / ImageDecoder 在后台解码、校正方向、限定最长边 1920 并编码为 JPEG，保存到专用私有暂存目录。

电视确认后将同一私有文件系统内准备好的 JPEG 原子重命名到目标分类，刷新 SceneView 缓存。放弃、退出、暂停或错误不会替换旧图。退出时关闭监听和连接、停止任务、释放预览与二维码、移除玻璃视图注册并清理暂存。网络变化通常在 5 秒内检测。

拒绝重复上传时先发送完整响应，再有界处理残余输入，避免连接复位遮住“先处理上一张”的提示。

## 兼容性与来源

最低 API 28、targetSdk 35。厂商网络隔离、浏览器内置扫码限制、图片格式支持和电视真实待机仍需真机验证。

二维码算法收录 Project Nayuki 的 MIT 开源 Java 源文件，版权说明见 THIRD_PARTY_NOTICES.txt，来源和文件摘要见 checks/qrcode_sources.json。没有二维码网络请求或新增 Gradle 依赖。

平台和代码依据：
- https://developer.android.com/privacy-and-security/local-network-permission （局域网套接字权限与 targetSdk 关系；核对日期 2026-10-20）
- https://developer.android.com/reference/android/graphics/ImageDecoder （API 28 解码与目标尺寸）
- https://www.nayuki.io/page/qr-code-generator-library （二维码源代码与 MIT 授权）
