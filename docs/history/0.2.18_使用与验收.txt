栖屏 0.2.18 · 遥控器待机唤醒直播

你反馈的情况：使用遥控器关机再开，“立即试播”能正常打开直播。
0.2.17 只处理新的系统重启，不会在普通待机唤醒时重新打开。本版为遥控器关开增加独立选项。
是否为这台海信电视的实际触发原因，还需要结合升级后的待机记录验证；没有假定电视一定发送标准唤醒信号。

一、升级后这样设置
1. 在 Android Studio 打开 qiping-launcher-v0.2.18，沿用自己的原签名覆盖安装，不必卸载旧版。
2. 首页齿轮 → 全部设置 → 开机与桌面。
3. 确认“默认桌面”为栖屏，“直播应用”为你的直播软件。
4. 开启新增的“待机唤醒也打开直播”。新开关默认关闭，旧的开机开关不会被更改。
5. 按返回回到首页，用遥控器关机，等屏幕关闭后再开启。
6. 回到栖屏首页并就绪后，应显示 3 秒倒计时，然后请求打开直播应用。倒计时期间先不要按其他键；按返回、方向键、确定或触摸会取消本次。

“开机自动打开直播”：用于真正系统重启。
“待机唤醒也打开直播”：用于遥控器待机再唤醒。
两个开关可以分别设置；都开启时不会因为同一轮触发而连续打开两次。

二、这次重点验证
□ 遥控器关开后，看到 3 秒倒计时，并打开直播。
□ 从直播按返回回到栖屏，停留几秒，不会再次跳进直播。
□ 在直播应用内部关机再开，保持原应用；再按返回回到栖屏，不补启动直播。
□ 再关开一次，在倒计时中按返回：本次保持桌面。
□ 下一次重新关开，仍能正常打开直播。
□ 关闭“待机唤醒也打开直播”后，遥控器关开保持桌面；原系统重启开关的状态不变。
□ 原绑定、收藏、排序、壁纸、字号、玻璃样式和手机传图仍正常。

三、如果仍然没有自动打开
先不要反复切换开关，以免覆盖最近记录。
进入“开机与桌面 → 启动状态”，拍下：
  - 待机唤醒自动打开是否开启；默认桌面；直播应用。
  - 最近唤醒记录。
  - 电源监听信息。
也可进入“运行诊断 → 查看最近记录”，或导出 TXT。

最近记录能区分：未检测到待机 / 唤醒、等待桌面前台、等待默认桌面、等待应用、被按键取消、超时、请求已发出。
“已发送打开请求”不保证直播软件内部已经开始播放。

四、行为边界
从栖屏首页待机后，只有栖屏回到前台、屏幕处于交互状态、没有打开弹窗且首页就绪时才执行。若电视唤醒后仍停留在其他应用，栖屏不从后台强制切换。
唤醒后最多等待 60 秒。超过时间再返回桌面，不补启动；期间的遥控器 / 触摸操作可取消。
如果进程被系统清理且没有观测到唤醒时刻，不凭旧的关屏记录猜测开机。状态会说明，可在回到栖屏后再试一次完整关开。
没有增加后台常驻服务、唤醒锁或新系统权限；不会为了监听而阻止电视休眠。
栖屏自己的空闲壁纸时钟不是系统待机，不会触发此功能。

五、开发与模拟器
Android 9 / API 28 及以上；compile / target 35，versionCode 20。
沿用 JDK 17 / 21、AGP 8.7.3、Gradle 8.9、SDK Platform 35 / Build Tools 35.0.0。
源码包不含 APK、签名、SDK 或缓存。
在独立模拟器中先设栖屏为默认桌面、开启待机开关、回到首页；通过模拟器电源按钮关开进行测试。
也可使用 adb shell input keyevent 223 进入休眠，再用 adb shell input keyevent 224 唤醒。
主机序列检查和 Android 模拟器结果见“验证记录.txt”；海信原厂遥控、CEC、快速启动行为需要你实际验收。

手机裁剪、明暗适配和运行诊断的详细说明保留在 docs/history/0.2.17_使用与验收.txt。
